# P02-T03 — Refine approved direction and design system

**Phase:** P02  
**Status:** complete  
**Authorization:** user-approved-2026-11-04 (no production release)  
**Dependencies:** P02-T02

## Objective

Create the design system and representative page designs from the approved concept, code-first in HTML/CSS under `design/` (ADR-005).

## Repository context

Shared foundations plus content-led section systems; important design decisions trace to code.

## Scope

- Typography/color/spacing/grid/motion
- Section-specific systems and components
- Focus/hover/error/reduced-motion states
- Responsive page/prototype designs
- Token/component mapping

## Preconditions

- A concept has explicit user approval
- Owner feedback available on the code-first specimens in `design/system/`

## Ready-to-copy prompt

> Refine only the approved concept. Define shared tokens and justified section-specific systems. Design responsive states, keyboard/focus, reduced motion and accessible equivalents. Map the specimen tokens and components to proposed site tokens/components. Obtain progressive section approvals.

## Acceptance criteria

- [x] Approved direction documented (DESIGN.md "Approved so far")
- [x] Accessibility states designed (specimen States section; mapping.md "States")
- [x] Specimen-to-code token/component mapping exists (`design/system/mapping.md`)
- [x] Unapproved sections marked provisional (each page design says "layout provisional"; mapping.md marks every token and component)

## Validation commands

```bash
Open design/system/index.html and inspect its tokens and states
Review representative pages at 1440, 834 and 390 px in Chromium, Firefox and WebKit
```

## Expected deliverables

- `DESIGN.md revisions`
- `design/system/ specimen pages`
- `design records`

## Evidence required

- Approvals, specimen paths, check results and deviation history

## No scope creep

- Do not code unapproved directions
- Do not force all spaces into one style
- Do not compromise contrast
